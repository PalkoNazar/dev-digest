## Goal
When the plan is done, the PR Overview tab has a PR Brief block. Before any brief exists it offers **Generate brief**. After generation it shows:
- an optional verdict banner from the latest review (P3);
- the brief summary;
- a left column with the existing Intent card and Risk areas;
- a right column with the existing Blast radius card;
- a full-width "Review focus — read these first" list.

The existing Description section stays below the block. Each focus item and risk file reference opens Files changed on that file and line. The target lives in the URL (`?tab=diff&file=…&line=…`) and is added with a history push. The target file is expanded, scrolled into view and its line highlighted, in Smart and Original order.

The new `brief` module serves two routes:
- `GET /pulls/:id/brief` reads only the cache.
- `POST /pulls/:id/brief` generates a brief:
  - **Facts:** the stored intent, the blast radius map, per-file +/- with Smart Diff role and changed line ranges (numbers only), PR title and description, up to 3 linked issues, and the union of Project Context docs attached to any agent or skill of the repo.
  - **Budget:** 8,000 tokens (ceil(chars/4)), cut in the spec's order.
  - **Model call:** exactly one structured call on the `risk_brief` feature model, all untrusted text behind `INJECTION_GUARD`.
  - **Grounding:** risks and focus items are checked against PR files ∪ blast map, then capped.
  - **Storage:** stored in `pr_brief.json` with the head SHA, plus a stale flag.

The spec's Non-goals stay out (Prior PRs, auto-generation, MCP tool, reviewer-prompt feed, Graph toggle, CI runner).

## Risks
- **The S2 move changes intent or Smart Diff behaviour by accident** (a constant value, regex, `REF_MAX_CHARS` ≠ 120, the rule order). Mitigation: `git mv`, identical values, existing `intent-refs`/`smart-diff`/intent service tests unchanged except imports, plus the smoke review run. The `reviews/AGENTS.md` lines that name `smart-diff/classify` and the intent refs location go stale; doc-writer updates them after the last run.
- **`_shared/` becomes a dumping ground.** Mitigation: two focused files named by responsibility (`pr-refs`, `file-roles`) plus one constants file; nothing else moves.
- **The port fed by `container.reviewRepo` couples the brief to the `ReviewRepository` facade's method shape.** Mitigation: the port is structural and minimal (`getIntentRecord` → `{ record }`); a rename breaks typecheck in `brief/routes.ts`, not at run time.
- **A sync POST can take up to ~90 s.** No Fastify `requestTimeout` is configured (unverified for the Node default). Mitigation: the single-flight promise is independent of the request, and GET re-reads on remount.
- **Strict json_schema with a nullable `line`.** Mitigation: the TourDraft precedent.
- **Blast caller lines refer to `index_sha`, not the PR head.** This is accepted by the spec (AC-97 compares against map lines).
- **Nested card chrome in the two-column layout.** Mitigation: wrapper styles only; the cards are not changed.
- **jsdom lacks `scrollIntoView`.** Mitigation: stub it per test file (S11).
