## Goal
When the plan is done, the PR Overview tab has a PR Brief block. Before any brief exists it offers **Generate brief**. After generation it shows:
- an optional verdict banner from the latest review (P3);
- the brief summary;
- a left column with the existing Intent card and Risk areas;
- a right column with the existing Blast radius card;
- a full-width "Review focus — read these first" list.

The existing Description section stays below the block. Each focus item and risk file reference opens Files changed on that file and line. The target lives in the URL (`?tab=diff&file=…&line=…`) and is added with a history push. The target file is expanded, scrolled into view and its line highlighted, in Smart and Original order.

The new `brief` module serves two routes:
- `GET /pulls/:id/brief` reads only the cache.
- `POST /pulls/:id/brief` generates a brief:
  - **Snapshot:** one consistent PR + files read; refused when the files are not at the head commit.
  - **Facts:** the stored intent, the blast radius map, per-file +/- with Smart Diff role and changed line ranges (numbers only), PR title and description, up to 3 linked issues, and the union of Project Context docs attached to any agent or skill of the repo.
  - **Budget:** 8,000 tokens (ceil(chars/4)), cut in the spec's order.
  - **Model call:** exactly one structured call on the `risk_brief` feature model, all untrusted text behind `INJECTION_GUARD`.
  - **Grounding:** risks and focus items are checked against PR files ∪ blast map, then capped.
  - **Storage:** stored in `pr_brief.json` with the SHA of the snapshot it used; the stale flag is computed on read and updated on an open page when the PR head moves.

The spec's Non-goals stay out (Prior PRs, auto-generation, MCP tool, reviewer-prompt feed, Graph toggle, CI runner).

## Risks
- **The S2 move changes intent or Smart Diff behaviour.** Mitigation: `git mv`, identical values, the existing tests and the smoke review. Doc-writer updates `reviews/AGENTS.md` lines naming the old paths.
- **`_shared/` grows into a dumping ground.** Mitigation: two files named by responsibility plus one constants file.
- **A PR whose detail refresh keeps failing can't get a brief** (409 until resync). This is intended (review #1): the message tells the user to resync; it is better than a brief stamped with the wrong commit.
- **Repeatable-read tx on the snapshot.** Postgres supports it; Drizzle passes `isolationLevel` (unverified in this Drizzle 0.38 setup — the implementer confirms the option name; fallback: a single query joining `pull_requests` and `pr_files`, which is also one snapshot).
- **Timeout overlap:** after a 90 s timeout, a manual retry can run while the old transport is still open (≤ 5 s until the adapter aborts at 95 s), so a second paid call is possible only on an explicit user retry. Accepted and documented (review #10).
- **Failed-call usage is logged as `null`** (the adapters drop usage on schema failure); cost tracking of failed calls is incomplete. Adapter changes are out of scope (review #9, rejected part).
- **Sync POST up to ~90 s;** no Fastify `requestTimeout` is set (Node default unverified). Mitigation: a request-independent promise, and GET on remount.
- **Strict json_schema + a nullable `line`.** Mitigation: the TourDraft precedent.
- **Blast caller lines refer to `index_sha`.** Accepted by AC-97.
- **jsdom has no `scrollIntoView`/layout.** Mitigation: stubs; scroll asserted by call target only.
